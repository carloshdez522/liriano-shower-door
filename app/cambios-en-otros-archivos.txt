## 1. common.js  (archivo compartido)

### i18n — nuevas claves en 'en' y 'es':
  records_search_ph, records_export_csv, records_stats_total,
  records_stats_count, records_no_results, records_changes, edited

### Nueva constante: STORAGE_KEY_RECORDS = 'liriano_records'

### Nuevas funciones para almacenamiento de historial:
  loadLocalRecords(), saveLocalRecords(), nextLocalRecordId()
  createRecord(job, status) — crea entrada en el historial con snapshot
  getRecords(), getRecordById(id), deleteRecord(id)

### Modificadas:
  updateJob(id, data) →
    - Ahora hace merge (Object.assign) en vez de reemplazar el job entero.
    - Detecta si data es un cambio parcial de status (toggle) o una edición
      completa: si es parcial usa data.status como recordStatus; si es
      edición completa usa 'edited'.
  toggleJobStatus(id) → ahora pasa solo { status: ... } a updateJob
    (antes pasaba el job completo).
  toggleJobDone(id) → ahora pasa solo { status: 'done' } a updateJob
    (antes pasaba el job completo). Más seguro y evita doble carga.
  createJob(data) → sin cambios.

### Nuevas exportaciones:
  window.createRecord, window.getRecords, window.getRecordById, window.deleteRecord

### Nueva función: loadSeedFromScript()
  Inyecta un <script src="data/jobs.js"> dinámicamente para cargar datos
  iniciales cuando localStorage está vacío (funciona con file://, a diferencia de fetch).

### Modificada: getJobs()
  Ahora intenta 2 estrategias para seed inicial cuando localStorage está vacío:
  1. fetch('data/jobs.json') — cuando se sirve via HTTP (CORS disponible)
  2. loadSeedFromScript() — fallback para file:// (usa <script> tag)

### Nota: migrate-on-read (en record.js)
  Si no hay records al abrir la vista, se seedean desde los jobs existentes.
